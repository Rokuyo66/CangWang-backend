# 江湖事件 · 劇本格式（草案，2026-10-21）

稿紙：`dev/design/journal/sheet.html` 的「江湖事件」分頁（發佈在「道緣劇本稿紙」artifact，雲端存檔的 `jianghu` 那一欄）。
**後端還沒接**：這份是稿紙存的格式，也是之後建表、寫抽事件邏輯的依據。

## 跟角色事件分工

| | 角色事件（`character_events`，EVENT-SCRIPT.md） | 江湖事件（本檔） |
|---|---|---|
| 主角 | 三位角色（你陪著） | 你（三位是路上遇到的人） |
| 目的 | 向玩家立起角色形象 | 收集你自己的稱號 |
| 結構 | 線性章節、一次性、正史 | 短局，從事件池抽，可重玩 |
| 開放 | 道緣＋修為門檻 | 修為門檻；局數另訂（經濟） |
| 獎勵 | 他的身分、他的衣裝 | 你的稱號（`player_titles`） |

**鐵則**：會改變你和三位關係的事只寫在角色事件。江湖裡他們可以登場、說話，但不能發生跟主線打架的事。
江湖一局結束只把「結局摘要」寫進記憶，不寫逐句。

## 一程（一份文件）

```jsonc
{
  "id": "jh_xxxxx", "title": "下山採藥", "summary": "…",
  "require_cultivation": 0,          // 修為門檻（境界的數字，同 REALMS）
  "length": 6,                       // 一局抽幾件事
  "stats": [{ "k": "s1", "name": "心" }, { "k": "s2", "name": "緣" }, { "k": "s3", "name": "劫" }],
                                     // 三項隱藏數值；k 固定，name 可改。玩家看不到數字
  "opening": { "bg": "guanmen", "text": "卯時，你揹著藥簍出了觀門。" },
  "events": [ /* 事件池，見下 */ ],
  "endings": [ /* 結局表，見下 */ ]
}
```

## 事件

```jsonc
{
  "id": "sxxxx", "title": "山路遇雨",
  "weight": 1,                       // 抽籤權重
  "once": true,                      // 一局只出一次
  "step": [1, 99],                   // 能出現在第幾件到第幾件（99＝不限）
  "gua": ["kan", "zhen"],            // 綁卦象：本卦上卦或下卦是其中之一才抽得到；[]＝不限
  "need": { "s1": [2, null] },       // 數值條件：到這件事之前累積的值；[下限, 上限]，null＝不限
  "scenes": [                        // 幕：格式同 EVENT-SCRIPT.md（who／me／speaker／portrait／text／choices／end）
    { "text": "雨下得急。", "choices": [
      { "key": "c1", "label": "去樹下躲", "fx": { "s3": 1 } },          // fx：選了之後數值加減
      { "key": "c2", "label": "冒雨趕路", "fx": { "s1": 1 }, "to": "end" } // to：本件裡的幕 id，或 "end"＝這件事結束
    ]}
  ]
}
```

## 結局

由上往下比，`need` 全部符合的第一個就是這一局的結局。**最後一個 `need` 必須是空的**（保底）。

```jsonc
{ "id": "sxxxx", "title": "藥簍裝滿", "rare": false,
  "need": { "s1": [4, null] },
  "text": "結語一段",
  "player_title": { "label": "採藥人", "desc": "圖鑑上那一句", "call_as": "" } }
```

## 一局怎麼跑（稿紙「試走一局」照這個做；後端之後也照這個）

1. 起一卦，取本卦的上卦、下卦（八卦 key：qian dui li zhen xun kan gen kun）。
2. 數值全部從 0 開始。演開場。
3. 第 n 件（n＝1…length）：候選＝`step` 包含 n、`gua` 為空或含上／下卦、`need` 符合、`once` 的沒出過；照 `weight` 抽一件。
   候選是空的就提早收尾。
4. 演那件事的幕；選項的 `fx` 加到數值上；`to` 跳幕或結束這件事。
5. 跑完 length 件（或提早收尾）→ 比結局表 → 發那個結局的稱號（已有就不重發）。

待定（之後跟經濟一起訂）：每天幾局免費、多玩的成本、稀有結局在圖鑑上的提示方式、後端的表（建議 `jianghu_routes` 存整份 JSON、`jianghu_runs` 記每局走過的事件與結局）。
