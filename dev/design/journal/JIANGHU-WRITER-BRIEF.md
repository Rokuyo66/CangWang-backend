## 二、遊戲規則（不能改的）

| | 規則 |
|---|---|
| 一卦一篇 | 玩家今天的日運卦是哪一卦，今天的江湖就是那一篇。64 卦各一篇 |
| 六爻＝六節 | 依序演初爻→上爻六節。日運卦**哪一爻是動爻，那一節就多演「變數」**幾幕；沒動就不演 |
| 動爻機率 | 每一爻每一趟**約 1/4** 會動（各爻獨立）；再走一趟會重搖 |
| 次數 | 每天第一趟免費；再走一趟花靈石 |
| 主角 | 玩家。預設身分「幾知觀下山的弟子」；故事真的編不進去才用偽裝身分。入場選本名或化名，劇本裡一律寫 `{名}` |
| 生死 | **玩家與三位主角不會死**。本篇人物可以死，某些結局寫死也行——讓人想再走一次去救他 |
| 三位主角 | 大師兄、師妹、觀貓可以客串（觀裡派你下山、回觀求助、事後問他），**不改變他們和玩家的關係**；不靠他們也要走得完 |
| 數值 | 全江湖共用五項：`s1` 義、`s2` 智、`s3` 名、`s4` 情、`s5` 財。**選了之後才在畫面上跳動**，選之前玩家看不到每個選項加什麼 |
| 財＝盤纏 | `s5` 是錢。劇本可以給入場盤纏（`start`）；選項可以標花費（`cost`），不夠的選項照樣列出但反灰、寫原因 |
| 結局 | 六節演完，由上往下比結局表，第一個符合的就是它；最後一個是保底（沒有條件） |
| 第一次走到某結局 | 發靈石、可發稱號、可在某位主角記憶裡留一件事，談心多一顆「去問」 |
| 成就 | 一卦可以好幾個，亮了之後玩家在 App 自己點領取靈石 |

## 三、寫作規則（演出）

**總原則：演出來給玩家看，不要旁白交代。** 設定（誰欠誰、誰收了錢、告示是誰換的）要藏在人物的話、動作、物件裡，
讓玩家自己拼起來。六六的原話：「設定要演給玩家看」「寫劇本以把故事說清楚為先，不以分鐘數設限」。

### 3.1 一幕
- 一幕＝畫面上一次對話框。**`text` 裡的換行（`\n`）就是一句一句的單位**：App 照換行排版，
  下一句放不下就清掉、從那一句重新開始。所以：
  - 一段（兩個換行之間）**最好 60 字內，最多 120 字**；太長的段落 App 會被迫在句號處切開。
  - 一幕通常 1～4 段。
  - 要在同一幕裡**強制清掉框、從頭重寫**（例：沉默一拍再開口），寫 `//`（全形 `／／` 也行），前後不用再換行。
- 說話者三種寫法：
  - 三位主角：`"who": "daoshi_m" | "daoshi_f" | "lingshou"`
  - 玩家自己說：`"me": true`（台詞照樣寫在 `text`，用「」）
  - 本篇人物：`"npc": "n_aqin", "speaker": "阿芹"`（`npc` 要在 `npcs` 裡）
  - 都不寫＝旁白（畫面上置中、淡色）。
- 台詞用「」，旁白不加引號。一幕可以混：「台詞。」\n她把信遞給你。\n「台詞。」
- **不要寫「你說：」**——玩家選的那句話會自己留在畫面上。
- **不要用＊動作＊**（那是談心閒聊的寫法）。動作寫成旁白句；三位主角的台詞一樣用「」。
- 說話者 `speaker` 跟人物表的 `name` **一字不差**（不要一下「老倉吏杜伯」一下「杜伯」）。身分寫在 `desc` 或旁白裡。
- **劇本文字不能有條件**：不要寫「若你之前核過帳，桌上便多了四支筆；若沒有……」。玩家走到哪一幕就演哪一幕；
  不同的前因要演不同的內容，就用選項 `req`／`to` 分成兩條路，或交給結局表處理。
- **不要寫爻位標題**（不要「初九・潛龍勿用」這種字卡）。爻的意思要藏在劇情裡（範本：初爻的人「潛」著不敢出頭）。
- `{名}` 會換成玩家的名字。不要寫死性別：玩家可能是任何人。
- 立繪 `portrait`：**不寫＝沿用上一幕**；寫人物 id＝換成那個人；寫 `null`＝收起。換場景（`bg`）時立繪自動收起，新場景第一幕要自己指定。
- 場景 `bg`：換場時才寫（同一場景的後續幕不要重寫）。`place`＝換場時畫面上打出的地名（例：「雲渡口」「萬金號・帳房」）。

### 3.2 選項
- 一個選擇點 2～4 個選項。`label` **16 字內**，是玩家說的話（用「」）或做的事（不用引號）。
- `hint` 是選項下面的小字，**12 字內**，給氣氛或代價（「水冷得刺骨」「一兩碎銀」），**不劇透數值、不寫攻略**。
- 選項之間要是**真的兩難**，不是「好選項／壞選項」。範本：替婆婆付渡錢（花錢、得人情）vs 撕告示（拿證據）vs 去找魁首（衝動、得名聲）。
- 每一篇大約 8～12 個選擇點。主線（不含變數）參考 2500～4000 字。

### 3.3 三位主角的口吻（客串時）
| | 稱呼玩家 | 怎麼說話 |
|---|---|---|
| 大師兄（代理掌門） | 護道人／直呼名字 | 精準、保守、話少；在意人時不說關心的話，而是替你備好東西、指出風險；常引「師傅說……」（師傅＝觀貓）。範本：「亢龍有悔，切莫躁進。」 |
| 師妹（幾知觀管事） | 施主／直呼名字 | 溫潤、會看臉色、話說得周到；底下其實警覺、算計；用錢大方、直接把事情解決。範本：「三兩，省著點花。觀主不在，師兄走不開。」 |
| 觀貓（觀寵，其實是師傅） | 鏟屎的／兩腳獸／小子 | 毒舌、慵懶、看破世事；講重話不解釋；在意也嘴硬。範本：「卦什麼卦，她要的是有人下山。」 |

### 3.4 結局文字
- `text`：結局那一段，2～4 段。**用人物的下場收**，不要寫「你成長了」「你明白了」這種感想。
- `insight`：**一句**領悟，最好就是那一卦的爻辭或卦辭（範本：「見群龍无首，吉。」「亢龍有悔。」）。
- `npc_fate`：一句話記本篇人物的下場（給成就榜看，例：「凌霄墜柱，傷了一條腿」）。
- 稱號 `player_title.label` 4 字內、`desc` 一句話。

## 四、邏輯規則

### 4.1 結構
- `nodes` **剛好 6 節**：`nodes[0]`＝初爻 … `nodes[5]`＝上爻。每一節 `title` 是給編輯看的小標（App 不打）。
- 每一節的 `scenes` 依序演；有 `choices` 的那一幕等玩家選。
- `to`：選了跳到**同一節裡**某一幕（那一幕要有 `id`），或 `"end"`＝這一節到此結束。不寫＝演下一幕。**不能跨節跳。**
- `end: true`（幕上）＝演完這一幕，這一節就結束（用在分支走完、不要接著演後面的幕）。
- **分支要收回來**：兩條路的幕排在同一節裡時，前一條路的最後一幕要 `end: true` 或選項 `to`，不然會一路演進另一條路。
- **前路銜接 `after`**（幕上，選填）：`"after": ["c33","c34"]`＝這一趟**前面選過其中任一個**才演這一幕；不符合就跳過、順著演下一幕（連它的 `end` 也不算）。
  空著＝人人都演。最常用在變數：同一段變數依前面怎麼選，開頭接不同的話，後面再接共同的幕。範本：乾為天上爻的變數——
  攔下／同登／拆旗的人看到沈捕頭來帶人、喊「上去！」的人只看到「來晚了」。`after` 只能填**在這一幕之前**出現的選項 key。
  **不要再用文字寫條件**（「若你之前……」）：要分前因就用 `after`。

### 4.2 數值 `fx`
- 一個選項 `fx` 加減 1～2，最多動兩項。整篇下來，一個數值大概落在 0～8。
- 五項都要有選項會改到（財除了 `cost` 也可以用 `fx` 收錢，例：收了賄賂 `s5: +5`）。
- **數值只能表示「傾向」。** 決定性的事（做了某件不可逆的事）用旗標，不要用數值門檻去猜。

### 4.3 財（盤纏）
- `start: { "s5": 3 }`＝入場帶 3 兩。`cost: 1`＝這個選項要花 1 兩，選了扣掉。
- 設計時算一下：**每條路上最多花得到多少**，不要讓關鍵選項永遠付不起（除非就是要逼玩家去拿錢）。
- 同一幕所有選項都付不起時，App 當這一幕沒有選項、照常往下演——不要依賴這個行為，當作保險。

### 4.4 道具 `get`／`req`
- `get: "道具名"`＝選了拿到。`req: "道具名"`＝身上有才看得到這個選項（沒有就整個不顯示）。
- 每一個 `req` 都要有某個選項 `get` 它，而且 **`get` 要在 `req` 之前的節**（或同節更前面）。
- 道具名 2～6 字，是具體的東西（「萬金號帳本」「沈捕頭的名帖」），玩家在結局卡上看得到。

### 4.5 旗標 `set`
- 暗的，玩家看不到，只給結局判斷用。記的是「做了哪件事」（例：`揭局`、`登柱`、`拆旗`）。
- 每個結局用到的旗標都要有選項會設它。

### 4.6 結局表（最容易出錯的地方）
- 由上往下比，**第一個符合的就是它**。所以**越特別、條件越嚴的放越上面**，保底放最下面。
- 條件：`need: { "s1": [下限, 上限] }`（`null`＝不限）、`flags: [要有的]`、`not_flags: [不能有的]`、`moves: [爻號]`（這幾爻的變數這一趟都要演到，`0`＝初爻、`5`＝上爻），全部都要成立。
- **稀有結局用 `moves` 做**：靠哪一爻動才走得到就寫進 `moves`，每多一爻機率乘 1/4（範本：潛龍在淵＝`moves: [5]`＋旗標「隨捕頭去」，約 1/4 再看玩家選不選）。
- **最後一個結局條件全部留空**（保底）；保底以外的每一個都要有條件，否則它會擋住下面所有結局。
- 建議 4～6 個結局：一個稀有（`rare: true`）、一個本篇人物死亡或重大損失、一個「看清但不出手」、一個保底。
- 每個結局都要真的**有一條路走得到**（第五節要逐條證明）。
- **小心「條件寫在變數幕裡」**：只有某一爻是動爻才演得到的選項，它設的旗標／給的道具，一趟只有約 1/4 機率出現。
  拿它當結局條件，那個結局就變成靠運氣——可以，但要是刻意的（標 `rare`），並寫進機率表。
  （六六 10-22 的乾為天改版就是例子：紙鶴在五爻的變數裡，所以「龍柱之上」只有五爻動時走得到。）

### 4.7 懸念 `hook`
- `{ who: 主角 id, ask: 玩家帶去問的那句, memory: 那位主角知道的事 }`。三樣都要寫，`memory` 是寫進那位記憶的事實（第三人稱、一兩句）。
- 用在想讓玩家「回觀裡聊這件事」的結局，一篇 1～3 個就好。

### 4.7b 共用人物（六六 2026-10-24：不一定每次都新增人物）
江湖是同一個世界：沈捕頭、褚萬金這種人可以在好幾卦出場。之後道籍會有「圖鑑」，**每位人物會記玩家在幾卦裡見過他（事件完整度）**，
所以新的一卦**先看能不能用現成的人**，故事真的需要才開新人物。

- 複製出來的稿裡有「能沿用的共用人物」名單（別卦已經出場、立繪已經有）。要用就把那一列照抄進 `npcs`，**`id` 一字不改**——同一個 id＝同一個人、同一張立繪 `char/<id>`。
- 跨卦是同一個人：**身分、性格、口吻、在意的事不能變**。處境可以變（換了差事、落魄、搬到別鎮），但要在劇情裡交代得通。
- **每一卦都要單獨看得懂**：玩家每天的卦是隨機的，可能先遇到「後面」的事。可以提一句別卦的事當彩蛋（「上回在雲渡……」），不能要玩家走過那一卦才看得懂。
- **共用人物不寫死**：可以受傷、下獄、離開，寫在 `npc_fate`；別卦再出場時，不假設那個結局發生過（各卦的結局彼此平行）。
  會在某個結局死掉的人（例：凌霄在「亢龍有悔」墜柱），就不要拿去別卦當現役人物；要用只能寫成往事或傳聞。
- 開新人物時，`desc` 寫清楚他是誰、待在哪、靠什麼過活——好讓之後別卦接得上。`id` 用 `n_<拼音>`，全江湖不能撞名（撞名＝被當成同一個人）。
- 美術表：沿用的人不用再開立繪；要新的表情或衣裝，在表裡寫「沿用 `char/<id>`，另要…」。

### 4.8 成就
| kind | 亮的條件 | 建議 |
|---|---|---|
| `ending` | 走到某個結局（填 `ending`） | 綁最想讓人追的結局（通常是稀有那個） |
| `endings_all` | 所有結局都走過（累計） | 每篇一個 |
| `changes_all` | 每一爻的變數都演過（累計） | 六節都有變數時才放 |
| `items_all` | **一趟之內**帶齊劇本裡所有道具 | 算機率：道具散在變數幕裡就很難，見第五節 |
| `run` | 一趟之內：帶著 `items`（列出的道具）、走完時數值在 `need` 範圍內、（選填）走到 `ending` | 給「特定玩法」的成就，例：「不花一文錢走到飛龍在天」＝`need: { "s5": [3, null] }, ending: …` |

- 一篇 3～5 個成就。`desc` 是玩家看得到的提示，**寫成謎面，不寫攻略**（範本：「讓龍旗不再屬於一個人。」）。
- 靈石（暫定，六六還會調）：結局第一次達成 20～50、成就 30～80；越難越多。

## 五、交稿前自檢（每一條都要實際做）

### 5.1 路線表（必交）
每個結局寫一條路：動爻設定 → 每個選擇點選哪個 → 走完時的數值、道具、旗標 → 由上往下比，確認**停在這個結局**，
而且**沒有被上面的結局先接走**。格式：

| 結局 | 動爻 | 選擇（依序，寫 label 前幾個字） | 走完時 義/智/名/情/財、道具、旗標 | 為什麼是這個結局 |
|---|---|---|---|---|

### 5.2 機率表（有用到變數幕時必交）
凡是結局或成就要靠某幾爻動才拿得到：寫出要哪幾爻動、一趟的機率（每爻 1/4，k 爻同時動＝(1/4)^k）。
1/16 以下的要說明這是刻意的。

### 5.3 清單（照稿紙的自動檢查＋人工檢查）
- [ ] `nodes` 剛好 6 節，每一節都有內容
- [ ] 每個選項都有 `label`；每個 `to` 都指到同一節裡存在的 `id`
- [ ] 每個 `req` 都有選項 `get` 它，而且拿得到的時間在前
- [ ] 沿用的共用人物 `id` 跟名單一字不差；性格、身分跟別卦一致；沒有把共用人物寫死
- [ ] 每個 `after` 填的 key 都是這一幕**之前**的選項；有 `after` 的幕，不符合的人跳過後接得上下一幕
- [ ] 每個結局用到的旗標都有選項 `set` 它
- [ ] 最後一個結局沒有條件；其他結局都有條件
- [ ] 每個結局都有名字、`insight`；有 `hook.who` 的，`ask` 與 `memory` 都寫了
- [ ] 每位本篇人物都有出場；至少一個結局寫了 `npc_fate`
- [ ] 五項數值都有選項會改到
- [ ] 沒有「你說：」；沒有爻位字卡；沒有寫死玩家性別
- [ ] 每一段（換行之間）120 字內
- [ ] 分支走完都收回來了（不會一路演進另一條分支的幕）
- [ ] **「理想的那個選項」真的會設理想結局要的旗標**：玩家照直覺選最好的答案，要走得到最好的結局（坤為地初稿：最完整的方案沒設「開倉」，反而要選「先開一日急糧」才進得了理想結局）
- [ ] **保底結局一個條件都沒有**（連 `not_flags` 都不能有）：不然總有一些走法什麼結局都不符合，玩家那一趟會白走
- [ ] 沒有＊動作＊；說話者名字跟人物表一致；文字沒有「若……若沒有……」這種條件句
- [ ] 有 `cost` 的選項：那條路上錢夠不夠，寫在路線表
- [ ] 前後一致：死掉／離開的人沒有在後面出場；物件、時間（白天／夜裡）、地點接得上
- [ ] 成就：`ending` 綁的結局存在；`run` 至少指定一樣條件；`items_all` 一趟真的帶得齊（寫出路線）
