# 語系：繁體、簡體、英文

六六 2026-10-20 定的方向：

- **繁簡**：設定裡切換，全部內容跟著換。✅ 已做（前端 `claude/intelligent-sagan-dskwzh`）
- **英文**：卦面上的字（卦名、卦辭爻辭、六親、地支……）**不翻**，「強迫學中文」；
  介面、問問題、解卦走英文。閒聊原文不翻，每則給「翻成英文」按鈕，按了才翻（逐則、付費模型）。

## 一、繁簡（已做）

| | 做法 |
| --- | --- |
| 設定 | 道籍›設定「語言」：繁體中文｜简体中文。存本機 `zhVariant`（跟字級一樣，只影響這台裝置）。沒選過時，系統語言是 zh-CN／zh-SG／zh-Hans 就預設簡體 |
| 轉法 | 前端 `src/app/zh-variant.js`：原始碼、後端、劇本**一律只寫繁體**，簡體是畫出來之後才轉。MutationObserver 轉文字節點＋`placeholder／title／aria-label／alt`；canvas 的 `fillText／strokeText／measureText` 包一層（批文存圖、卦圖）；本機通知送出前過 `zhOut()` |
| 轉換表 | opencc-js 1.0.5 的 `t2cn`（台灣正體→大陸簡體），內嵌約 70 KB（`build.mjs` 1b'）。App 不准跑遠端下載的程式碼，所以不走 CDN |
| 不轉 | 輸入框裡使用者打的字、textarea、contenteditable、標 `data-zh-keep` 的元素 |
| 成本 | 0。不打 AI、不打後端 |
| 字型 | 現用的 Noto Serif TC 子集裡簡體字都有字形（风门书龙卫…抽查皆有），不必另載 SC |

**踩過的坑**

1. **乾 → 干**：OpenCC 把「乾為天」轉成「干为天」、「乾下坤上」轉成「干下坤上」。
   卦名的乾在簡體也寫乾。`zh-variant.js` 先把乾藏起來，只有後面接 淨燥脆枯涸旱癟杯貨糧洗爽咳渴瞪笑 的才轉成干。
   之後若發現別的字也被錯轉，加在同一處。
2. **程式拿畫面上的字做判斷**：`ui/motion.js` 的等候點認「載入…」——簡體下變「载入…」就認不得。已補兩種字形。
   新程式**不要拿 `textContent` 去比中文字**；要比就比資料，不比畫面。
3. **切回繁體要重新載入**：轉過去的字回不來（不存原文，省記憶體）。

**還沒涵蓋**

- 桌面小工具（Android 原生 RemoteViews 畫的）：仍是繁體。要做就在 `WidgetJob` 讀同一個偏好，Java 端用 OpenCC4J 或小字典轉。
- 使用者用簡體發的廣場貼文，繁體使用者看到的是簡體原文。要統一就在後端 `post_create` 存之前過 `s2t()`（`_shared/chat.ts` 已有，含干支保護）。

## 二、英文（規劃）

### 要翻的與不翻的

| | 英文版 | 誰做 |
| --- | --- | --- |
| 介面文字 | 英文 | 前端抽字串 |
| 問事（使用者的問題） | 英文直接收 | 不必做事：模型本來就讀得懂 |
| 解卦（批文） | 英文 | 後端：`interpret` 收 `lang:"en"`，提示裡加輸出語言 |
| 卦名、卦辭爻辭、六親、世應、地支 | **中文原樣**，批文裡第一次出現時括號附拼音與一句英文意思 | 後端提示詞 |
| 閒聊 | 角色照中文回；每則一顆「Translate」 | 新 mode `translate` |
| 劇情事件、站內信、觀中誌 | 先不翻（之後同閒聊做法：按鈕翻） | — |
| 條款 | 英文版另寫，不機翻 | 人工 |

### 工作量（2026-10-20 實數）

前端介面字串（不含註解、條款、卦理資料）：

| 資料夾 | 字串數 | 中文字數 |
| --- | ---: | ---: |
| `src/main` | 1,215 | 6,838 |
| `src/pages` | 253 | 2,797 |
| `src/xinji` | 204 | 1,026 |
| `src/markup` | 152 | 634 |
| `src/story` | 107 | 697 |
| 其他 | 30 | 136 |
| **合計** | **約 1,960** | **約 12,100** |

繁簡可以「畫完再轉」，英文不行：句子裡夾變數（「剩 ${n} 天」）、語序不同、複數，必須在程式裡抽成 `t("key", {n})`。
這是英文版最大的一塊，建議分批：先抽**新手一定會走到的路徑**（登入、入場、問事、看批文、方案頁），約佔三成，其餘頁面先維持中文。

另外：英文字比中文寬 1.5～2 倍，按鈕、頁籤、頂列要逐頁看版面（六六說的「光介面就要調一陣子」）。

### 翻譯按鈕的成本

模型用閒聊同一顆 Haiku 5.5（`0085`：輸入 $0.10、輸出 $0.50／百萬 token）。

| | token | 費用 |
| --- | ---: | ---: |
| 輸入：指令＋術語表約 200＋一則回覆約 60 | 260 | $0.000026 |
| 輸出：英文約 80 | 80 | $0.000040 |
| **每則** | | **≈ US$0.00007 ≈ NT$0.002** |

一個人一天按 100 則，一個月約 NT$6——閒聊本身才是成本。所以：

- **以整則為單位翻**（不是逐句），成本一樣，呼叫少很多
- **翻過的存起來**：`chat_messages` 加 `translations jsonb`（`{"en": "..."}`），同一則再按不再打模型
- **免費**，但走 `rate_minute` 限流，計入 `ai_usage`（kind `translate`）
- **術語表**放後端常數（卦名、六親、角色名、觀中專名的固定譯法），每次翻都帶，否則同一卦每次翻得不一樣

### 後端要動的

| 項目 | 位置 |
| --- | --- |
| `interpret` 收 `lang`（`zh-Hant`｜`en`）；`zh-Hans` 不必傳，前端自己轉 | `interpret/index.ts` 驗身分那一段讀進來，往下傳 |
| 批卦提示詞：`lang==="en"` 時加輸出語言與「卦面原樣」規則 | `_shared/pipeline.ts` |
| 英文模式跳過 `s2t()`、`fixGuaciChars()` | `_shared/chat.ts` 的 `polish`（第 1354 行一帶） |
| `translate` mode＋快取欄位 | 新 `_shared/translate.ts`；migration 加 `chat_messages.translations` |
| 術語表 | `_shared/glossary.ts` |

## 三、上架與付款的語系

- Google Play／App Store 的商店頁要各自準備繁中、簡中、英文三份描述與截圖。
- 簡中市場：Google Play 在中國大陸不可用；簡中主要是新馬與海外華人。iOS 上架中國區還需要 ICP 備案與 AI 生成內容的相關審批，**建議先不開中國區**。
