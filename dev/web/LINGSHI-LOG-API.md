# 靈石收支列表契約（待接：前端 repo）

收支頁原本是一筆一列的流水。一晚上聊十七句就是十七列「閒聊 −1」，把當天真正想看的
東西（加卦扣了幾顆、追問問了什麼）擠到看不見。改成「當天 × 項目」一列，展開才看每一筆。

後端這一側已改完（`node dev/ledger-test.mts`，14 條）。前端要接的是 `days`。

---

## 回傳長什麼樣

`POST /functions/v1/interpret`，body `{ mode: "lingshi_log" }`，回：

```jsonc
{
  "kind": "ok",
  "truncated": false,          // true = 撈滿上限，最舊那天已被拿掉（見下）
  "since": "2025-07-19T…",     // 這次查詢的起點（近 30 天）
  "days": [
    {
      "date": "2025-08-18",    // 台北日
      "income": 6,             // 當天收入（正）
      "spend": -30,            // 當天支出（負，與每一筆同號）
      "net": -24,              // income + spend
      "groups": [
        {
          "action": "chat",
          "label": "閒聊",      // 中文名後端給，前端不必自己再翻一份
          "count": 17,
          "amount": -17,       // 這一列的合計，等於底下 items 相加
          "items": [
            { "id": 8123, "at": "2025-08-18T12:18:00Z", "amount": -1,
              "detail": null, "ref": null, "refKind": null }
          ]
        },
        {
          "action": "extra_cast", "label": "加卦", "count": 2, "amount": -20,
          "items": [
            { "id": 8090, "at": "2025-08-17T17:22:00Z", "amount": -10,
              "detail": "這份工作還能做多久",   // 這筆扣款買到的東西
              "ref": "cast-uuid", "refKind": "cast" }
          ]
        }
      ]
    }
  ],
  "logs": [ … ]                // 原本的逐筆流水，暫時保留
}
```

## 畫面怎麼畫

- 不展開：每天底下一列一個項目 —— `閒聊 −17`、`加卦 −20`、`追問 −8`。右邊那個數字用
  `group.amount`，不是 `count`。
- `count > 1` 才需要那顆展開的小 icon；`count === 1` 直接把 `items[0]` 的時間攤在同一列
  就好，點開只有一筆是白點一下。
- 展開：照 `items` 畫，時間用 `at`（已是新→舊）、金額用 `amount`。
- `detail` 有值就顯示（追問顯示的是**追問那一句**，不是原卦問句；加卦顯示原卦問句）。
  已截短到 40 字並補上 `…`，前端不必再截。
- `ref` + `refKind` 是可以點進去的東西：`"cast"` → 卦曆那一卦，`"post"` → 廣場那一篇。
  兩者皆可能為 null（閒聊、簽到、突破這種沒有對照物的）。
- 群組與天都已經是「最近的排前面」，直接照順序畫，不要再排一次。

## `truncated` 要處理

流水取窗有上限（目前 600 筆）。撈滿代表最舊那天很可能只撈到一半，
**後端會把那一天整天拿掉** —— 一列寫著「閒聊 −12」而實際是 −40，比不顯示更糟。
所以 `truncated: true` 時列表底部請給一句「僅顯示近期紀錄」之類的說明，
不然人會以為那天憑空消失了。

## `logs` 什麼時候可以拿掉

`logs` 是原本那份逐筆流水，形狀沒變（`action`／`amount`／`created_at`），
留著只是為了讓還沒改的前端不會空白。畫面換成 `days` 之後跟我說一聲，
後端這一欄就拿掉。

## 明細接不回去的兩種情況

- **舊的加卦**。加卦的扣款發生在卦入庫之前，`ledger.ref_id` 一直是空的，往後由後端在
  卦入庫後補接。歷史資料用 `0041` 補了一輪，但只補「那三分鐘內只有一支卦、那支卦也只被
  這一筆指到」的；同一分鐘連起兩卦（收支頁上並排的兩筆「加卦 01:22」就是）配不出誰是誰，
  一律留空。認錯卦等於在錢的紀錄上說謊，寧可不補。
- **追問**。`ref_id` 存的是卦 id 不是追問 id，後端以時間就近配對回那一句追問；
  配不到（當時 AI 失敗、追問沒入庫）就退回顯示原卦問句。
