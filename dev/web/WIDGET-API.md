# 桌面小工具 API（待接：前端 repo ／ App widget）

後端這一側已完成並測過（`node dev/widget-test.mts`，14 條）。
視覺原型可直接開來看：`node dev/build-widget.mjs` → 瀏覽器開 `dev/widget.html`
（三種尺寸 × 五套配色 × 未測／四個等第，全部可切）。

一支 mode 就是全部：`POST /functions/v1/interpret`，`Authorization: Bearer <JWT>`，
body `{"mode":"widget"}`。錯誤一律 200 ＋ `{kind:"err", msg:"…"}`。

---

## 這一支刻意沒有的東西

先看這一段，否則會照著 `profile` 的習慣接，然後發現有一半欄位不存在。

**沒有額度。** `castFreeLeft`／`chatFreeLeft`／`followFreeLeft` 一個都不回。
問卦鈕上不標「今日剩 N 卦」——觀主定的：桌面上先算帳會讓人不問。
前端就算想標也標不出來，這是刻意的。

**沒有國曆。** 回應裡沒有任何一個 `YYYY-MM-DD`。電腦與手機都有系統時鐘，
再印一次只是佔掉那行小字。小字走農民曆那一套：`ganzhi.line` ＝「丙午年丁酉月丙戌日」。

**沒有批文。** 日運的完整批文留在 App 裡，小工具只給 `fortune.castId`——
點下去用深連結開 App 的那一卦。小工具上塞不下三百字，塞了也沒人在桌面上讀。

**不呼叫模型。** 行止（宜守／且行）由等第硬對應（見下表），所以同一天無論刷新幾次
都是同一個詞。模型每天講法不同，那在對話裡是優點，在桌面上是 bug。

**這一支不寫任何一列。** 純讀。簽到與抽日運各自呼叫既有的 `signin`／`daily_fortune`。

## 回應長這樣

```jsonc
{
  "kind": "ok",
  "ganzhi": { "year": "丙午", "month": "丁酉", "day": "丙戌", "kong": "午未",
              "line": "丙午年丁酉月丙戌日" },       // 小字直接印 line 即可
  "jieqi":  { "name": "白露", "dayIndex": 3, "isToday": false,
              "asset": "bailu",                     // 襯底圖資產鍵，見下
              "line": "白露第3日，鴻雁來，玄鳥歸。" },
  "sign":   { "done": true, "streak": 4 },
  "fortune": {                                      // ① 今日已測
    "done": true,
    "castId": "3f1c…",                              // 深連結進 App 讀批文
    "tier": "daji", "tierLabel": "大吉",
    "stance": { "key": "xing", "label": "且行",
                "line": "勢在你這邊：該開口的開口、該決的決，別再等一個更好的日子。",
                "yi": ["出行","開口","決事"], "ji": ["猶疑","空等"] },
    "qian": { "n": 36, "gz": "己亥", "poem": ["福如東海壽如山", "…共四句"] }
  },
  "themes": {
    "owned": ["bamboo"],
    "list": [
      { "key": "paper",     "name": "宣紙", "locked": false, "price": null },
      { "key": "night",     "name": "夜觀", "locked": false, "price": null },
      { "key": "bamboo",    "name": "竹簡", "locked": false, "price": 260 },
      { "key": "cinnabar",  "name": "硃砂", "locked": true,  "price": 260 },
      { "key": "porcelain", "name": "青花", "locked": true,  "price": 320 }
    ]
  },
  "lingshi": 128
}
```

今日未測時 `fortune` 換成這個形狀（只有兩個欄位，沒有 `stance`）：

```jsonc
"fortune": { "done": false, "hint": "今日的氣還沒測——先抽一卦，才知道是宜守還是且行。" }
```

還有第三種：`done:true` 而 `tier`／`stance`／`qian` 皆為 `null`。
那是「閘門記了今日已測、但那一卦撈不到」的殘局（極少見）。
不要退回一個看起來很正常的「平」——照實顯示「今日已測」並把人帶回 App 就好。

## 行止：四個等第 → 桌面上那一個詞

| tier | tierLabel | stance.label | 宜 | 忌 |
|---|---|---|---|---|
| `daji` | 大吉 | **且行** | 出行　開口　決事 | 猶疑　空等 |
| `ji` | 吉 | **可行** | 小成　修補　問人 | 貪大　躁進 |
| `ping` | 平 | **守常** | 照舊　整理　對帳 | 更張　新約 |
| `shou` | 宜守 | **宜守** | 守成　養息　觀望 | 動土　爭執　借貸 |

四級用「進退」而非「吉凶」講：小工具是每天要看的東西，天天被斷吉凶會膩，
被指出今天該進還是該守才用得上。最差一級講的是宜守而非凶——
桌面上每天都會出現的東西，不該有一天是勸退的（門檻見 `_shared/fortune.ts`）。

文案的唯一出處是 `_shared/widget.ts` 的 `STANCE`。那一支是純的（不碰 supabase、
不讀 `Deno.env`），前端可以直接 import 進 bundle，不要另抄一份——
原型 `dev/widget/entry.ts` 就是這樣接的。

`shou` 那一級 `tierLabel` 與 `stance.label` 同字。畫等第徽章時要判掉，
否則同一行會出現兩次「宜守」。

## 三顆鈕怎麼接

| 鈕 | 何時出現 | 做什麼 |
|---|---|---|
| **問卦** | 永遠。整張小工具上最重的一塊顏色 | 開 App 的問事流程 |
| **今日簽到** | 永遠（`sign.done` 決定樣式） | `mode:"signin"` |
| **測今日運勢** | 只在 `fortune.done === false` | `mode:"daily_fortune"` |

問卦不在小工具裡完成——問事要打字、要擬題、要選角色，那是 App 的事。
小工具負責的是把人帶進去，所以它只需要一個深連結。

**簽到的斷簽分支要留意。** `mode:"signin"` 可能回 `kind:"broken"`
（斷簽了，問要不要花靈石補簽）。小工具上放不下那個對話，
收到 `broken` 就別在小工具裡處理，直接開 App 的簽到畫面讓人在那裡決定。

**`daily_fortune` 會呼叫模型，慢。** 別在小工具裡等它——開 App，讓抽卦在 App 裡跑完，
回來刷新小工具即可。小工具點下去要在 100ms 內有反應，那個反應就是「App 開了」。

## 配色

五套：內建二（宣紙、夜觀）＋ 付費三（竹簡、硃砂、青瓷）。
內建那兩套不入 `profiles.owned_themes`（見 `0033`），所以 `list` 裡它們永遠 `locked:false`。

**付費牆規則：App 裡沒解鎖的，小工具也不給用。** 解了竹簡，小工具才選得到竹簡。
`locked:true` 的請照樣列出來並標價——看得到買不到，才有人買。
點下去不要在小工具裡賣，開 App 的配色頁。

**但兩邊可以各選各的。** 桌面用夜觀、App 裡用竹簡，是合理的，不要強制同步。
所以「目前選哪一套」是小工具自己的偏好設定（存在宿主端），不存後端；
後端只回「哪幾套解得開」。

色票在前端（原型 `dev/widget/entry.ts` 的 `PALETTES`），後端一個色碼都不管。
每套七色 ＋ 一層可選材質：

| key | 名 | 底 | 卡 | 墨 | 印記 | 材質 |
|---|---|---|---|---|---|---|
| `paper` | 宣紙 | `#F2EBDA` | `#FFFDF8` | `#221E1A` | `#B5402E` | — |
| `night` | 夜觀 | `#12100E` | `#1A1714` | `#E8E0D4` | `#A8623F` | — |
| `bamboo` | 竹簡 | `#3E432F` | `#CDB884` | `#2C3120` | `#9C4A2E` | 直紋（簡與簡之間的縫） |
| `cinnabar` | 硃砂 | `#20100D` | `#361A15` | `#F2DED4` | `#C0483A` | 右上暈開 |
| `porcelain` | 青花 | `#C9D6CE` | `#EDF3EF` | `#22302B` | `#B5402E` | 冰裂 |

材質不是裝飾——竹簡沒有那道直紋就只是一張黃紙，而配色要賣得掉，
靠的正是「一眼看得出是哪一套」。

> key 與名稱以前端 `part2.html` 的 `THEME_FREE`／`THEME_PAID`／`THEME_LABEL` 為準，
> 已對齊。兩個容易猜錯的：宣紙是 `paper`（不是 `xuan`），`porcelain` 叫**青花**（不是青瓷）。

## 節氣襯底圖

`jieqi.asset` 是節氣包那 24 張貼紙的資產鍵（與 `0053_sticker_jieqi.sql` 的
`stickers.id`／`asset` 同一組字串，不是另取的一套拼音）：
`assets/stickers/jieqi/<asset>.webp`。24 張圖已經在前端 repo 裡了。

Android 小工具讀的是 APK 內 `assets/public/stickers/jieqi/`——`cap sync` 把
`dist/` 整包放在那裡，所以原生端與網頁用的是同一份檔案，換圖不必動原生程式碼。

它是襯底，不是插圖：壓在右側、透明度一成上下、不要蓋到問卦鈕。
`asset` 為空字串或圖檔載不到時要有退路——原型退成節氣二字的大字。
小工具可能跑在還沒下載資產的機器上，那時也不能開天窗。

節氣二十四張圖是買斷的貼紙包，但**襯底用的那一張不受購買狀態限制**：
它是日曆的一部分，不是玩家的收藏。

## 三種尺寸放什麼

高度是系統給死的，而小工具不能捲動——所以每一格都是取捨，不是「都放進去」。

| | 小 2×2（176²） | 中 4×2（376×176） | 大 4×4（376²） |
|---|---|---|---|
| 干支小字 | 兩行 | 一行 ＋ 節氣第幾日 | 同中 |
| 節氣 | 只有名 | 名 ＋ 第幾日 | 同中 |
| 行止 | 大字 | 大字 ＋ 等第徽章 | 同中 |
| 建議句 | ✗（放不下） | 兩行截斷 | 三行 |
| 宜／忌 | 只有「宜」 | ✗ | 宜 ＋ 忌 |
| 籤詩 | ✗ | ✗ | 籤號 ＋ 四句 |
| 底列 | 簽到 ＋ 問卦 | 同 | 同 |

小尺寸只放「宜」：那是三個詞就能看完的東西，而一句話不是。

## 什麼時候刷新

`widget` 是純讀的輕請求，但它仍然是一次網路來回。該刷的時機只有四個：
跳日（過台北 00:00）、宿主把小工具帶回前景、從 App 切回桌面、使用者手動下拉。
**不要定時輪詢**——內容一天只變幾次，而它變的那幾次都有事件可接。

離線時不要清空，但要分兩段看：干支與節氣本來就是算得出來的（`_shared/jieqi.ts`
與 `core.ts` 的干支都是純函式），照算照畫；行止則要比對快取那一份的日干支——
同一天就照舊顯示，跨了日就換成「未測」。把昨天的且行留在今天的桌面上，
比顯示不出來更糟。
